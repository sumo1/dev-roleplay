# 为 tags 字段加 GIN 索引而不是全文索引

> 日期：2026-06-01
> 作者：task-designer（规划阶段决策）

## 背景

需要给 `todos.tags` 字段（`string[]` 类型）加索引以支持按标签过滤。候选方案：

1. **GIN 索引**：针对数组字段原生支持
2. **全文索引（GIN + tsvector）**：把 tags 拼接成文本后全文索引
3. **普通 B-tree 索引**：单元素查询场景

## 决策

选 GIN 索引，理由：

- 数据库原生支持数组 `@>`（包含）操作，查询语义清晰
- 不需要额外的表达式计算（全文索引方案需要触发器或 generated column）
- 性能对当前数据量（预估百万级以内）足够

## 被否决的方案

- **全文索引**：增加复杂度，没有"搜索短语"这种语义需求，全文索引是过度杀伤
- **B-tree 索引**：无法直接支持数组包含查询，需要把 tags 展开成独立表，改动过大

## 证据

- 本项目其他数组字段的查询也用 GIN 索引（见 `migrations/20250815-add-user-roles-gin.sql`）
- 规划阶段人工 review：需求方确认不需要"模糊匹配"或"相关性排序"
