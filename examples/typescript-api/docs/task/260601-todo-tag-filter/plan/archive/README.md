# Plan Archive

被推翻或合并掉的子任务 plan 文件归档于此。

## 何时归档

- 子任务被后续决策**推翻**——拆分方式变了、功能被砍掉、合并到了其他 step
- 整个步骤被**重新规划**——新版本写在 `plan/{name}.md`，旧版本搬到这里

## 何时不归档（直接删）

只有"从未被引用过的草稿"且"没有任何决策痕迹"才删。**有过历史影响的 plan 永远归档不删**——它的存在本身就是"我们曾经考虑过这条路"的证据。

## 归档时要做什么

1. 在文件头部加一行 `> [已归档 YYYY-MM-DD] 原因：{被哪条决策推翻 / 合并到哪个新 step}`
2. 在 `progress.md` 的"决策记录"里加一条指向归档原因的 memory 条目
3. 任何引用旧路径的文档（含 SUMMARY）更新为指向 archive 路径
