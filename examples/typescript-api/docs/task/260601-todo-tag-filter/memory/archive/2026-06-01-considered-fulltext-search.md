# [已归档 2026-06-02] 考虑过用全文索引（GIN + tsvector）支持 tag 过滤

> 日期：2026-06-01
> 作者：task-designer
> [已归档 2026-06-02] 原因：被 [`../2026-06-01-tag-index-decision.md`](../2026-06-01-tag-index-decision.md) 推翻。GIN 数组索引足够，不需要全文索引。

## 背景

最初想：tag 过滤可以重用更通用的"全文搜索"基础设施——把 tags 拼成文本，用 GIN + tsvector 全文索引。

未来如果产品要"todo 内容搜索"也能复用同一索引。

## 为什么后来被推翻

- 全文索引需要触发器或 generated column 来维护 tsvector，复杂度比 GIN 数组索引高一倍
- "未来可能要全文搜索" 是猜想，不是确认需求——为不存在的需求加复杂度
- GIN 数组索引天然支持 `tags @> ARRAY[...]`，语义清晰

## 保留的价值

记录"曾经考虑过全文索引"——如果未来真的要做全文搜索，下一任务可以从这里看到当时为什么没顺手做，以及具体的权衡数据。
