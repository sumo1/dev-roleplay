# tag 参数校验正则：`^[a-zA-Z0-9_-]{1,50}$`

> 日期：2026-06-02
> 作者：task-designer

## 背景

`GET /todos?tag={name}` 的 `tag` 参数需要校验。候选放宽程度从严到松：

1. 严格：`^[a-z0-9-]{1,30}$`（小写 + 数字 + 短横线）
2. 中等：`^[a-zA-Z0-9_-]{1,50}$`（大小写 + 数字 + 短横线 + 下划线）
3. 宽松：URL-safe 编码后任意字符

## 决策

选 **方案 2**：`^[a-zA-Z0-9_-]{1,50}$`

## 理由

- 现有数据库里实际的 tag 值同时存在大小写（`Work` / `work` / `URGENT`），方案 1 会把现有数据排除掉
- 长度上限 50 与现有实体里 tag 的最长记录（30 字符）有冗余，但不夸张
- `_` 和 `-` 都允许，与项目里其他 slug-like 字段约定一致

## 被否决的方案

- **方案 1**（严格）：会把现有合法数据查不到——破坏向前兼容
- **方案 3**（宽松）：开放注入面，且 GIN 索引对超长字符串性能下降

## 证据

- `SELECT DISTINCT unnest(tags) FROM todos LIMIT 100` 抽样：所有现有 tag 命中方案 2
- 单元测试覆盖：`Work` ✅ / `work` ✅ / `<script>` ❌ / 51 字符 ❌ / 空字符串 ❌
