# Engineering Principles — 跨任务通用工程原则

本目录沉淀从具体任务 memory 中蒸馏出的**跨任务通用原则**。

与任务级 memory 的区别：

- `docs/task/*/memory/` —— 某个具体任务的场景、决策、踩坑记录，随任务结束而固化
- `docs/knowledge/principles/` —— 多次在不同任务 / 不同场景中被验证的通用判断准则，新任务直接引用

## 上浮纪律

一条原则上浮到本目录前，必须**同时**满足：

1. 去掉任务专名后，结论**仍然成立**且**仍有信息量**
2. `docs/knowledge/` 或 `docs/engineering/` 里**尚未覆盖**同样的原则
3. 来源有**具体证据**——被推翻的假设、踩过的坑、讨论记录，不是空泛口号
4. 会驱动**情境化判断**（"情况 A 做 X、情况 B 做 Y"），而不是单向指令（"永远做 X"）

只满足"听起来很对"但无证据的条目，**不上浮**。

## 上浮后必做

- **脱敏**——去掉任务专属代号
- **加引用**——在 knowledge 条目末尾注明来源 task memory
- **双向链接**——原 task memory 条目头部加一行指向 knowledge 新条目

## 反向流动？

通常不发生：knowledge 不会被降级回 task memory。

**例外**：某条原则被新证据证伪时，归档到 `archive/` 子目录并保留"已归档"标记——归档不删除，保留审计价值。
